Command blocks

There are 3 different types of command blocks:

Impulse, Executes command once!

Repeating, Executes command repeatedly!

Chain, Executes command when triggered by another command block!

What are command blocks?​

Command blocks are like chat commands stored in block data, useful for automatic running, and linking of commands. Command blocks are obtained either through the /give @s minecraft:command_block or operator tab configured in accessibility settings.

Usual use cases

Usually minecraft commands are used in servers, adventure maps, demo scripts, or storage of commands.

Basic Configuration​

Before Use

Make sure the gamerule /gamerule command_blocks_work true is set to true.
If on a server make sure enable-command-block = true in the server.properties file.

When you configure a command block you have 3 options to choose from, the first one is the command input, the second one is the redstone condition, and the third one is the command block type.

Command input​

This field accepts any string input with or without the / symbol.

Redstone condition​

This field has 2 options, Needs Redstone and Always Active.

Conditions​

This field has 2 options, Conditional and Unconditional

Command block type​

This field has 3 options, Impulse, Repeating, and Chain.

Preview of UI​

Configuration​

As already known command blocks allow for storage of commands and these conditional statements like always active or Unconditional. With these we can stack command blocks and Configure command blocks to build off each other.
The most common configuration of command blocks is:

- Chain command block (Unconditional , Above repeating command block)
- Repeating command block (Always Active , Below pointing to chain command block)

Conditional VS Unconditional

Conditional command blocks activate only if the previos command returns true on a command, Unconditional commands activate without the need of another command use.

Limitations​

Usually minecraft command blocks and datapacks aren't too different on the ideals, but a huge issue with command blocks is its command execution is positioned where the block is. This means that command blocks can't execute a command outside of a players render distance.
There is also a limitation with running certain commands only reserved for datapacks like /function and /schedule commands.
Timing with command blocks are also tricky as the blocks because of the 0 ticks and 1 ticks mechanisms act all as 1 ticks.
